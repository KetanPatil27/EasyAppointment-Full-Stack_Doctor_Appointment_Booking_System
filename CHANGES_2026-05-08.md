## 🐛 Bugs Fixed

### `shx: not found` on Render build
- **Problem:** Backend build failed with `sh: 1: shx: not found`.
- **Root cause:** `shx` and `typescript` are in `devDependencies`. Render's build runs with `NODE_ENV=production`, which causes `npm install` to skip dev deps by default.
- **Solution:** Updated build command to `npm install --include=dev && npm run compile`.
- **Severity:** 🟠 High (fully blocking deploy)

### Same trap again on the frontend
- **Problem:** Frontend build failed with `Cannot find module '@tailwindcss/postcss'`.
- **Root cause:** Identical to above — `@tailwindcss/postcss` lives in `devDependencies` and Render's production-mode npm install skipped it.
- **Solution:** Updated frontend build command to `npm install --include=dev && npm run build`.
- **Severity:** 🟠 High

### Render auto-picked Node 26 → MongoDB Atlas TLS handshake failed
- **Problem:** Backend booted but immediately died with `tlsv1 alert internal error: SSL alert number 80` from MongoDB.
- **Root cause:** `package.json` engines said `>= 18.0.0`, so Render picked the absolute latest Node available (26.x). Node 26's stricter OpenSSL 3.x defaults negotiate TLS in a way Atlas free-tier didn't always like.
- **Solution:** Set `NODE_VERSION=22.11.0` (LTS) on Render. This was a *partial* fix — the TLS error eventually came back even on Node 22 (see the next bug for the real cause).
- **Severity:** 🟠 High (intermediate)

### `ERR_REQUIRE_ESM` from `isomorphic-dompurify`
- **Problem:** Backend crashed at startup with `Error [ERR_REQUIRE_ESM]: require() of ES Module @exodus/bytes/encoding-lite.js`.
- **Root cause:** `isomorphic-dompurify` (added on Day 1 for XSS sanitization) pulls in `jsdom` → `html-encoding-sniffer` → an ESM-only `@exodus/bytes` module. CommonJS Feathers code can't `require()` ESM on Node 22.
- **Solution:** Replaced `isomorphic-dompurify` with `sanitize-html` — pure JS, CJS-compatible, no DOM emulation. Same `allowedTags: []` semantics so no behaviour change.
- **Severity:** 🟠 High

### MongoDB driver v5 pin attempt — DEAD END
- **Problem:** Tried to downgrade `mongodb` to v5 to dodge the TLS issue.
- **Root cause:** `@feathersjs/mongodb@5.x` has *always* required `mongodb@^6` as peer dependency — there's no version of the Feathers adapter that accepts v5. A clean Render install fails with `ERESOLVE could not resolve`. Local installs may silently allow it via lockfile state, which is why the bug shipped.
- **Solution:** Reverted the pin. Stayed on `mongodb@^6`.
- **Severity:** 🟡 Medium (false fix — wasted one deploy cycle)

### ⭐ The real TLS culprit: missing `0.0.0.0/0` allowlist on Atlas
- **Problem:** All those TLS errors? Not Node, not driver, not region — Atlas's M0 free tier responds to non-allowlisted source IPs with `tlsv1 alert internal error` (alert 80) instead of a clean "IP not allowed" error. Hours of debugging chased the wrong layer.
- **Root cause:** The Atlas Network Access list was empty. Render free tier has no static IPs, so it must be `0.0.0.0/0`.
- **Solution:** Added `0.0.0.0/0` to Atlas Network Access. The mongodb-on-renamed-cluster issue immediately moved past TLS and onto the next layer (auth).
- **Severity:** 🔴 Critical (the most misleading error of the entire session — documented in `DEPLOYMENT.md` §11.6 to spare future devs the same loop)

### Bad-auth on Atlas
- **Problem:** Once TLS worked, the next error was `MongoServerError: bad auth: authentication failed`.
- **Root cause:** Wrong password / not URL-encoded.
- **Solution:** Regenerated the Atlas DB user password as alphanumeric-only (avoids URL-encoding traps), updated `MONGODB_URI` on Render. Confirmed locally with mongosh first, then updated Render.
- **Severity:** 🟡 Medium

### `ALLOWED_ORIGINS` JSON parse error on startup
- **Problem:** Backend crashed: `SyntaxError: __format parser error in ALLOWED_ORIGINS: JSON5: invalid character 'h' at 1:1`.
- **Root cause:** `custom-environment-variables.json` mapped `ALLOWED_ORIGINS` with `__format: "json"`. The Feathers config layer parsed the env var as JSON before any application code ran. A plain URL starts with `h` — invalid JSON.
- **Solution:** Wrapped the value in JSON array brackets: `["https://easyappointment-frontend.onrender.com"]`.
- **Severity:** 🟡 Medium

### Email delivery `ETIMEDOUT` on every send
- **Problem:** Every email attempt timed out: `[Email] Failed to send confirmation … code: 'ETIMEDOUT'`. Both `MAIL_USER` and `MAIL_PASS` were correct.
- **Root cause:** **Render's free tier blocks all outbound SMTP** (ports 25, 465, 587). No combination of Gmail/Mailgun/Brevo SMTP credentials would have worked.
- **Solution:** Switched the mailer to **Resend HTTPS API** (port 443, always allowed). Mailer module now picks the provider at runtime: Resend if `RESEND_API_KEY` is set, fall back to Nodemailer/Gmail for local dev, fall back to console.log if neither is configured. Removed the strict `MAIL_USER`/`MAIL_PASS` requirement at startup; a soft warning now logs when neither provider is configured.
- **Severity:** 🔴 Critical

## 🔧 Improvements & Refactoring

- **Email layer is now provider-agnostic.** Single `sendEmail` helper picks Resend HTTPS or Nodemailer SMTP based on env vars. Local dev keeps using Gmail; production uses Resend.
- **Cookie `SameSite` is now configurable** via `COOKIE_SAMESITE` env var. Required because `*.onrender.com` is on the Public Suffix List, so frontend ↔ backend on different subdomains is treated as cross-site by browsers — `SameSite=none` is mandatory there.
- **Structured error logs in mailer.** When email send fails, the log now includes SMTP code, response, and provider-config flags. Made debugging the SMTP block possible.

- `NODE_VERSION` — pinned to `22.11.0` (Render). Prevents Render auto-picking unstable latest Node.

## 📚 What I Learned Today

- **Atlas's TLS-error masking is the most misleading symptom in cloud-DB land.** A missing IP allowlist looks identical to OpenSSL incompatibility. Always check the allowlist *first*.
- **`*.onrender.com` is on the Public Suffix List** — different subdomains under it count as separate sites for SameSite cookie purposes. `SameSite=strict` blocks cross-subdomain cookies; production needs `SameSite=none; Secure`.
- **Render free tier blocks outbound SMTP** as anti-abuse. Any deploy that relies on Nodemailer + Gmail/Mailgun/Brevo will fail with `ETIMEDOUT`. Only HTTPS-based email APIs (Resend, SendGrid, Mailgun's API) work.
- **Always pin `NODE_VERSION` on a host** — never let "latest" be your bet. Node minor releases break native TLS handshakes more often than expected.
- **Peer-dependency trees are unforgiving on a clean install** even when local lockfiles tolerate them. Test against a fresh `npm install` before promising a fix.
