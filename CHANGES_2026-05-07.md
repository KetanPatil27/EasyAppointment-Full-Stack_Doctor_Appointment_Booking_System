## 🐛 Bugs Fixed

### Hardcoded JWT secret in committed config
- **Problem:** `config/default.json` contained the production JWT signing secret in plain text. Anyone with repo access could forge admin tokens.
- **Root cause:** Original Feathers scaffold defaulted to a literal value; nobody had moved it to an env var.
- **Solution:** Moved secret to `JWT_SECRET` env var via `custom-environment-variables.json`. Added a fail-fast guard in `index.ts` that refuses to start if the secret is missing, shorter than 32 chars, or matches the known-leaked value. Generated a fresh 256-bit hex secret for local dev.
- **Files affected:**
  - `backend/config/default.json`
  - `backend/config/custom-environment-variables.json`
  - `backend/src/index.ts`
  - `backend/.env`
  - `backend/.env.example` (new)
- **Severity:** 🔴 Critical

### JWT stored in `localStorage` (XSS risk)
- **Problem:** Frontend kept the access token in `localStorage`, where any injected script could read it.
- **Root cause:** Default SPA pattern; nobody had switched to httpOnly cookies.
- **Solution:** Backend now writes the token to an httpOnly `accessToken` cookie. Frontend uses `withCredentials: true` and stops touching the token at all. JWT strategy reads from cookie OR header.
- **Notable detour:** The first attempt put the cookie-issuing logic in a Feathers `after.create` hook, but `params.res` is filtered out by the v5 REST transport. Confirmed via diagnostic logging (`paramsKeys: [query, headers, route, provider]` — no `res`). Switched to an Express middleware that wraps `res.json` on `/authentication`. Verified end-to-end with curl (login response now includes `Set-Cookie: accessToken=…; HttpOnly; SameSite=Lax`).
- **Files affected:**
  - `backend/src/authentication.ts`
  - `backend/src/middleware/auth-cookie.ts` (new)
  - `backend/src/app.ts`
  - `frontend/services/api.ts`
  - `frontend/services/userService.ts`
  - `frontend/lib/app-context.tsx`
- **Severity:** 🔴 Critical

### No rate limiting on any endpoint
- **Problem:** Login and registration had no throttle — open to credential stuffing and email enumeration.
- **Root cause:** Greenfield project, never added.
- **Solution:** Added `express-rate-limit` with two tiers: a global limiter (100 req / 15 min / IP in production) and a strict auth limiter (5 *failed* attempts / 15 min / IP) on `/authentication`, `/users` POST, `/forgot-password`, and `/reset-password`. `skipSuccessfulRequests: true` so legit users with typos aren't punished. Production needs `trust proxy` so the limiter sees the real client IP.
- **Files affected:**
  - `backend/src/middleware/rate-limit.ts` (new)
  - `backend/src/app.ts`
- **Severity:** 🟠 High

### Slot booking race condition
- **Problem:** Two patients clicking "Book" within ~50ms could both pass the availability check before either wrote, ending up with two appointments on the same slot.
- **Root cause:** Code did read-then-write in two separate driver calls (`slotService.get` → `slotService.patch`), with no locking between them.
- **Solution:** Replaced with a single atomic `findOneAndUpdate({ _id, isBooked: false }, { $set: { isBooked: true } })`. MongoDB returns `null` on a no-match, which we map to a clean `409 Conflict` ("This slot is no longer available"). Same pattern applied to reschedule.
- **Files affected:**
  - `backend/src/services/appointment/appointment.hook.ts`
- **Severity:** 🔴 Critical (data integrity)

### No input sanitization (XSS + NoSQL injection)
- **Problem:** No layer of defense against `<script>` payloads in user-supplied text fields, or against `{"$ne":null}` operator-injection on POST bodies.
- **Root cause:** Greenfield project.
- **Solution:**
  - **NoSQL operator strip:** Custom Express middleware that recursively removes any object key starting with `$` or containing `.` from `req.body` and `req.params`. Crucially **does not** touch `req.query` — Feathers depends on `$limit`/`$sort`/`$or` URL operators.
  - **HTML strip:** Global Feathers app-level hook that runs DOMPurify (`isomorphic-dompurify` for now) with `ALLOWED_TAGS: []` on every string field in `context.data` for `create`/`patch`/`update`. Skips the `authentication` service path and skips fields named `password`, `imageData`, `avatar`, `profilePicture` so credentials don't get mangled and base64 images aren't churned through the parser.
- **Files affected:**
  - `backend/src/middleware/sanitize-body.ts` (new)
  - `backend/src/hooks/sanitize-strings.ts` (new)
  - `backend/src/app.ts`
- **Severity:** 🔴 Critical

### CORS hard-coded to `localhost:3000` and `:3001`
- **Problem:** Production deploy would silently fail with CORS errors because the array was hardcoded in source.
- **Root cause:** Default scaffold values, never made dynamic.
- **Solution:** New `cors-config.ts` with `resolveAllowedOrigins()` that accepts JSON array OR comma-separated string from `ALLOWED_ORIGINS`, plus `buildOriginValidator()` shared between Express CORS and Socket.IO. Server **fail-fasts** in production if the env var is unset. `maxAge: 600` caches preflight for 10 min. Validator logs blocked origins for ops debugging.
- **Files affected:**
  - `backend/src/middleware/cors-config.ts` (new)
  - `backend/src/app.ts`
- **Severity:** 🟠 High

## 📚 What I Learned Today

- **Feathers v5's REST transport filters `req`/`res` out of `params`** that reach service hooks. Anything that needs the Express response object has to live as middleware, not as a Feathers hook.
- **`SameSite=lax` works for `localhost:3000` ↔ `localhost:2029`** because both share `localhost` as the registrable domain — different ports are still same-site for cookie purposes.
- **MongoDB's `findOneAndUpdate` with a guard predicate is the canonical fix for read-then-write races.** Cleaner than transactions for single-document atomicity.
- **`SkipSuccessfulRequests: true`** on the auth limiter is the magic flag that keeps brute-force protection without punishing legit users — without it, a heavy admin would lock themselves out.
